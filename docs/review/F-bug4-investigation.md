### Alternative mechanisms
Enumerated and tested against the evidence; only M1 fits.
M1 (root cause, reproduced): CancelledError from feedback_watch_stop → _finish → _disarm → consumer.cancel() delivered while _notch awaited Desk.set_geq_band's /fx/5 type read, which calibration turned from a cache hit into a network round trip. Leaves no log line (not in _notch's except tuple), every other assertion passes, deterministic on Windows/CPython 3.12 (15.6 ms loop clock → the test busy-polls) with any real reply latency; probabilistic (∝ latency / 10 ms poll) on macOS/Linux; never on this sandbox's zero-latency shim.
M2 DeskError TIMEOUT on that same /fx/5 read (the seed hypothesis 'write raised and _notch swallowed it'): would produce the identical desync (plan committed, 'notch write failed (…): TIMEOUT: no /node reply for /fx/5', return None) but needs the desk silent for timeout_s×(retries+1) = 0.5 s in tests; calibration does not cause that, the FakeDesk answered in ≤5 ms in every run, and it WOULD have left a WARNING Jim's session would have seen. Same window, different trigger — fixed by the same change (and by removing the read).
M3 PolicyError RATE_LIMITED in acquire_write: bucket 50/s, a watch writes ≤1 cut per cooldown_s; not reachable here; would log.
M4 feedback_watch tool timeout (30 s) cancelling mid-arm: calibration is 2 s; and a cancelled arm leaves no session (cfs._arm try/except BaseException), so cfs_status would have shown idle — contradicts Jim's passing assertions.
M5 stale /fx/5/par served from the 2 s read cache to ring_out's preflight: ruled out — set_geq_band→_write invalidates the section (desk.py:883 via _leaf_index), the in-flight epoch guard (desk.py:269-272, 327-341) covers concurrent reads, and in every failing run the preflight get_fx was logged as a FRESH /node read returning par/22 '0.0' — the desk genuinely never received the SET. (slash()/send_raw() publish no write event but no GEQ path uses them.)
M6 SyntheticRta/loop-model artefacts (ring decays, cut reverted): the App's injected SyntheticRta is open-loop w.r.t. the FakeDesk GEQ; FakeDesk state showed par/22 never changed from 0.0; no restore/scene recall runs between stop and ring_out.
M7 queue/consumer starting late or calibration's subscribe blocking inside the lock: affects when detection happens (it did happen), not whether a committed cut is written.
Most plausible for Jim's description: M1 — it is the only mechanism that (i) is switched on purely by adding ~2 s between preflight and first cut (any 'run it after the frames start' placement, or the no-bail-out first draft), (ii) passes the notch/budget/report assertions while failing only 'already carries', (iii) logs nothing, and (iv) is effectively deterministic on his Windows 10 / CPython 3.12.14 desk PC.

### Calibration design
Implemented in worktree commit f9a5c56 (src/x32mcp/detector.py noise_floor / FeedbackDetector.set_floor / gate_db / level_offset_db; src/x32mcp/cfs.py _consume CALIBRATE phase, _install_floor, _await_floor; device.yaml detector floor_* keys; tests in tests/integration/test_cfs.py test_candidate_gate_is_calibrated_per_band_to_the_room_noise_floor, test_calibration_does_not_let_an_established_ring_hide_itself, test_ring_out_measures_the_floor_before_it_raises). Design:
WHEN/WHERE: as the first phase of the detector task itself (_consume), i.e. on the frame timeline: after set_rta_source and frames.start() by construction, discarding floor_settle_frames (the first frames after the source switch still show the old tap / auto-gain transient), then collecting floor_sample_frames or floor_sample_s (20 frames / 1.0 s; whichever first). Not in _open_session (no frames exist there — the HEAD code is a guaranteed no-op plus a 0.3 s stall) and not inline in _arm/feedback_watch (that holds CfsManager._lock and the tool call for the whole window, and — the bug — ages every cache entry the preflight primed past read_cache_ttl_s). Nothing is JUDGED while measuring (frames are sampled, det.feed is not called): the M7 failure was rumble notched 'within seconds of arming'; being blind for ~1.1 s after arm is the correct trade. The arming call returns immediately; CfsState.floor = {ready, measured, frames, floor_max_db/hz, floor_median_db, gate_min/max_db, capped_bands, master_db, floor_db[]} and the report's noise_floor block + a cfs.floor event expose it (auditability: 'why didn't it cut?'). Never stalls: if no frames arrive the ring-out waits floor_sample_s + 1.5 s grace, records 'noise floor not measured … using the configured gate' as a session warning and proceeds; watch simply goes live when frames come.
watch vs ring_out: identical code path (both arm → frames → CALIBRATE in the consumer). ring_out additionally awaits ses.floor_ready before its first RAISE (new CALIBRATE stage between ARM and RAISE; the master is at the operator's start level and 'nobody may play' — exactly the moment to measure), and after every successful raise sets det.level_offset_db = master_db − master_at_calibration so the per-band gates rise dB-for-dB with the gain the machine itself added (otherwise the room's own floor re-qualifies as the master comes up); the cap still applies after the offset. The ring_out pending/preflight tool call never arms, so it never calibrates (nothing to special-case). floor_ready is pre-set when floor_margin_db == 0 (calibration off → fixed gate, old behaviour).
STATISTIC: per band, not global. Room noise is coloured (HVAC/rumble 40-80 Hz can sit 40 dB over the 8 kHz hiss; the SyntheticRta's pink slope is the extreme case: its 20 Hz band at −9.5 dB set a GLOBAL gate of −1.5 dB and deafened 2.5 kHz — the reviewer's variant (a)). gate[i] = clamp(floor[i] + floor_margin_db, lo=min_level_db, hi=floor_cap_db): calibration only ever raises the configured gate and never above the cap. floor[i] = floor_percentile (0.9) quantile over the sample of min(level[i], median(±neighbour_bins neighbours) + prominence_db/2). High quantile rather than max (one transient/door slam must not set the session's gate; Jim's max-of-max over 40 frames is the least robust choice) and rather than median (the gate must clear the floor's own ±3 dB flutter, then + margin 8). The neighbourhood clamp is essential for the brief's 'ring already established when the detector arms' case: a narrow peak present during the sample would otherwise lift its own gate above itself and hide until it grew another 8 dB; clamped, it contributes what the broadband floor around it does and stays visible to prominence/override (test: a −40 dB established 2.4 kHz tone in the sample → gate there stays < −43 → notched right after CALIBRATE).
CAP: floor_cap_db (default −30 dBFS RTA; pick on hardware from a loud room, not the studio): anything louder than the cap is loud enough to be judged on prominence+growth alone, so a noisy room (or background music, M7) can desensitise the detector below the cap but can never deafen it to a real howl (M7's missed ring plateaued at −25). Bands whose floor+margin hit the cap are counted and produce a 'loud room … quiet the room for a cleaner calibration' session warning.
Interaction with prominence: prominence is the spatial floor (band vs its neighbours, same instant) — it rejects broadband lifts (master raised, crowd noise) but passes any stationary narrow peak forever (hum, a room mode, a held synth note); the calibrated gate is the temporal floor (band vs its own pre-arm history) — it rejects what was already there, narrow or not (up to the cap), but says nothing about new content. Feedback during a ring-out is narrow AND new AND rising relative to the pre-raise baseline, so requiring both is right and they do not double-count. Calibration is NOT a music/feedback discriminator: a bass line that starts after arming sails through it; the §1 frequency window / harmonic-family test is still the fix for the 40/80 Hz false positives. Optional next step (not implemented): a slow tracking floor (EMA τ≈2 s of non-candidate bands, frozen for bands within band_tolerance of a live candidate) for long watch sessions where the programme level drifts.
Also fixed: the _floor_db/_gate_db attributes that 56c34a7 put on CfsError.__init__ (cfs.py:122-123) are gone; DetectorConfig carries floor_margin_db (0 = off), floor_cap_db, floor_sample_frames, floor_sample_s, floor_settle_frames, floor_percentile with validation, so tests override them through detector_cfg like every other threshold.

### Desync fix
Implemented in worktree commit 73ab5f3 (kept in f9a5c56):
1. NotchController is two-phase (src/x32mcp/detector.py): propose(det, bus, session_id) -> NotchProposal|None is pure (band choice, depth, policy validate_notch; NO mutation); commit(proposal) -> Notch applies it (and refuses a stale proposal whose band gain moved). plan() remains as propose+commit for RecordingGeqWriter simulations only.
2. cfs._notch = propose → WRITE → commit: the write and the commit (+ confidence, notch_log, cfs.notch event, log line) live in one inner coroutine _apply_notch run as ses.notch_task and awaited through asyncio.shield, so cancelling the detector task (stop/_disarm) or the ring-out task (tool timeout, _unwind) can no longer split 'desk has it' from 'controller says so'. CancelledError is re-raised for the caller but the cut itself either completes whole or not at all. Write failures (DeskError/PolicyError/ConnectionError/CfsError) now leave NOTHING committed, add a session warning naming the band, and set ses.notch_error so a ring-out aborts with 'ring at N Hz not tamed: GEQ write for band B failed: …' instead of the false 'cannot cut deeper than −9 dB'.
3. _finish → _disarm → NEW _settle_inflight_notch(ses) BEFORE _build_report: an in-flight cut gets _NOTCH_SETTLE_S (1 s) to land (then it is on the desk, in the controller, in the report) or is cancelled uncommitted with the warning 'a GEQ cut was still in flight when the session ended and was abandoned (not applied, not reported)'. Regression tests hold Desk.set_geq_band inside an await across stop() and assert report == validate_ringout_eqs(desk) both ways (tests/integration/test_cfs.py test_stop_during_an_inflight_notch_write_never_reports_a_cut_the_desk_did_not_get / test_stop_lets_an_inflight_notch_write_land_and_reports_it; both FAIL at HEAD: state.notches non-empty while the write is in flight, and the desk never receiving a reported cut).
4. Close the window at its source and restore the detect→cut budget: Desk.set_geq_band(..., fx_type=None) skips its /fx/N /node read when the caller supplies the GEQ type; _DeskGeqWriter passes preflight's InsertInfo.fx_type (validated by validate_ringout_eqs, cannot change without a set_fx_type write or an xremote push, both of which invalidate). With the pre-write snapshot taken at arm and tokens in the bucket the cut path now has zero awaits before conn.set — on a real desk that removes a network round trip (0.25-0.5 s on a lost reply) from in front of EVERY cut, not just the test's.
5. Still recommended (not implemented): read-your-writes for cuts — after set_geq_band, confirm par/NN via get_fx (with the §5 settle / '/' echo barrier) before commit, retry once, else treat as failed; UDP SET has no ack, so 'sendto returned' ≠ 'the PA has the cut'. And reconcile at _finish: mark each reported notch applied/unapplied from a fresh GEQ read so _matched_session and the operator never trust controller memory over the desk.
Same commit-before-await shape elsewhere (audit): (a) cfs._arm's own comment (cfs.py:903-909): if the arm-time ensure_pre_write_snapshot fails, Desk._write retries the FULL desk dump inside the (former) plan→write window — seconds long; with propose/commit it is merely slow, but arming should refuse or re-snapshot explicitly rather than defer a multi-second dump into the first cut. (b) Policy.acquire_write (policy.py:393-395) reserves the bucket slot (_bucket_tokens -= 1) and then awaits sleep: a cancelled waiter leaks the reservation (bucket debt → spurious RATE_LIMITED later); refund on CancelledError. (c) _run_ringout/_write_master: a cancel between conn.set and `ses.master_db = after` (cfs.py:1191-1192) under-reports max_master_db by a step (the back-off is absolute so the desk ends safe, but the report understates what the room heard). (d) provision setup (setup_ringout_eqs) writes type → insert sel → on and validates immediately (BRIEF §5): a failure mid-sequence leaves the desk half-provisioned with no rollback and a misleading GEQ_VALIDATION_FAILED. (e) Cache-coherence footnote checked while ruling out the stale-read theory: every GEQ write goes through Desk._write → _invalidate_address (desk.py:883, 275-280) and X32Connection.set publishes 'write' (connection.py:530) → Desk._on_write_event; X32Connection.slash() and send_raw() publish no write event, but their only users are Desk.restore (invalidates everything itself), panic and the CFS emergency master restore (cfs.py:1338 — which therefore leaves a stale /bus/NN/mix section for up to 2 s after a connection-loss restore; harmless today, worth an invalidate).

## Investigator seeded with hypothesis 'cache-staleness' — confidence high, reproduced: True

### Calibration design
Placement: never inside _open_session (frames not running; also holds CfsManager._lock and delays the tool call) and never as a blocking 2 s await inside feedback_watch/_arm. Make it a session stage driven by the SAME consumer that feeds the detector (no second subscription): ARM → CALIBRATE (detector ingests frames, tracks candidates, emits nothing except the established-ring override) → LIVE. feedback_watch returns immediately with state.stage='CALIBRATE', floor/gate published in cfs_status and a cfs.stage event when it flips. For ring_out the frames only start at ARM after SNAPSHOT and _run_ringout currently raises the master immediately (cfs.py:1174) before a single frame has been seen; insert the CALIBRATE/LISTEN dwell between ARM and the first RAISE (floor_sample_s at the operator's start level, loop quiet by instruction) — it doubles as 'catch a ring that already exists at the start level before adding gain'. The pending (token-less) ring_out call never opens a session, so no special-casing is needed there (the existing _FLOOR_FIRST_FRAME_S bail-out addresses a path that does not exist). Skip the first ~5 frames after set_rta_source (source/auto-gain/PEAK switch settling).

Statistic: not max-over-frames of max-over-bands (cfs.py:845/870). That is (a) global — a −52 dB 48 Hz rumble sets the gate for 5 kHz where the floor is −80, so the real M7 events must climb ~35 dB before they are even candidates; (b) an extreme-value statistic — with ±3 dB RTA noise + wobble the max of 40 frames sits ~5 dB above typical, plus 8 dB margin; (c) poisoned by exactly the cases the brief lists: background music, or a ring already established at arm (the ring becomes 'the floor' and gates itself out forever). Use a per-band temporal baseline: floor[b] = low/median percentile (e.g. 50th of per-frame values, or 25th to be programme-robust) over the window, then spectrally smoothed with a running minimum/median over ±k bands with k wider than a ring (band_tolerance+leak ≈ ±2) and narrower than musical humps (≈ ±5, i.e. half an octave) so a narrow stationary peak cannot lift its own floor. Gate[b] = clamp(floor[b] + floor_margin_db, lo=min_level_db (config stays the floor-for-the-floor), hi=floor_cap_db). Cap: an absolute ceiling on the gate, ≈ −30 dBFS (M7's missed howl plateaued at −25; anything at or above −30 on a bus RTA is loud enough to matter in any room), so a loud room or walk-in music can never deafen the detector; log when the cap binds. Keep it running, not one-shot: in watch mode the human moves the master and programme changes, so maintain floor[b] as a slow tracker (attack seconds, release faster) that excludes bands currently held as candidates; in ring_out the machine knows every raise, so additionally shift the baseline by (master_now − master_at_calibration) dB at each RAISE instead of waiting for the tracker.

Interaction with prominence: prominence (level − median of ±neighbour_bins, detector.py:23/382) is already the spatial floor and does the discrimination; the absolute gate's only legitimate jobs are (1) ignore bands so quiet they cannot be regenerative and (2) stop digital-silence neighbours (−128) from manufacturing huge prominence. A per-band baseline+margin does both without a venue constant; it must stay well below the override_prominence path so an established ring (≥25 dB over neighbours) is emitted during CALIBRATE too. It is complementary to, not a substitute for, the frequency window (250 Hz–8 kHz) the brief identifies as the real fix for the 40/80 Hz false positives. Watch vs ring_out asymmetry: watch (human on the fader, music likely) → higher percentile robustness, tracker on, override allowed during CALIBRATE; ring_out (quiet by contract, machine drives gain) → shorter window (0.5–1 s), deterministic master-delta re-referencing, and treat 'floor+margin hits the cap across many bands' as a preflight-style warning ('room too loud to ring out'). On the SyntheticRta used by the tests a per-band median baseline gives ≈ −46 dB at 2.4 kHz → gate ≈ −38 dB, so the injected −34 dB ring qualifies immediately while the 20 Hz region gates at the cap — no test needs a magic number.

### Calibration design
Placement: never in _open_session (frames idle there, and it runs on ring_out's token call before SNAPSHOT/ARM) and never as an await inside the tool call/lock. Make it an explicit session phase executed by the detector task: _arm starts the source exactly as now; _consume begins in CALIBRATE state, collecting the first floor_sample_frames valid frames (len == bands, increasing ts) bounded by floor_sample_s of wall time, WITHOUT calling det.feed (so persistence/growth windows do not start on pre-gate frames and nothing can be notched by the uncalibrated detector), then builds the calibrated detector (`ses.det = FeedbackDetector(replace(cfg, ...))` or a `det.set_baseline(floor_per_band)` API), stores ses.floor_db / ses.gate_db / ses.floor_per_band on _Session (not on CfsError — cfs.py:122-123 is a slip — and not on the manager), publishes cfs.stage CALIBRATE -> ARMED, sets ses.calibrated (asyncio.Event). feedback_watch returns immediately with `calibrating: true, detector_live_after_s: floor_sample_s` in the result and summary ("detector live after a 2.0 s floor measurement — keep the loop quiet"); cfs_status exposes calibrated/floor_db/gate_db (+ per-band on request). ring_out: _run_ringout awaits ses.calibrated (timeout floor_sample_s + 1 s, else proceed with the configured gate and a warning) BEFORE the first RAISE; frames start at ARM after SNAPSHOT with the master at its untouched start level and nobody playing, which is precisely the quiet-loop condition a floor wants, so ring-out gets a true room floor for +2 s on a multi-minute run (add it to server._ring_out_timeout). If the source delivers no frame within _FLOOR_FIRST_FRAME_S keep cfg and say "uncalibrated" in state.
Statistic: per band, robust, never max-of-max. For each RTA band b take p90 (or median + 2·MAD) of its samples over the window -> floor[b]; a single kick/transient or one hot frame must not set the gate (the current `max(peaks)` of per-frame maxima is the worst possible estimator: one frame of one band decides). Candidate qualification becomes `level[b] >= max(cfg.min_level_db, min(floor[b] + floor_margin_db, floor_cap_db))` — i.e. the band must rise floor_margin_db above ITS OWN pre-arm level. Keep min_level_db as the absolute lower bound (calibration only raises). Only bands inside the detector frequency window (the planned detector.min_hz/max_hz ≈ 250 Hz–8 kHz) are calibrated/considered, so 48 Hz rumble or sub energy can never lift the gate for the 2–5 kHz region; report the loudest in-window floor as floor_db for humans.
Cap: detector.floor_cap_db (e.g. -30 dBFS RTA; must stay below the quietest real howl of interest, M7's was -25) applied per band; additionally if more than ~25 % of in-window bands hit the cap, flag `floor_suspect: true` + warning "floor measured over programme/noise; gate capped at -30 dB" in the arm result instead of silently deafening the detector (the SyntheticRta 'music' floor of -9.5 dB -> gate -1.5 dB is exactly that failure). A global scalar gate derived from the loudest band (current design) is wrong even with a cap: it lets LF programme energy set the threshold for HF feedback.
Watch vs ring_out: ring_out's floor is trustworthy (quiet loop by contract). In watch the band may be playing, so treat the measurement as a per-band baseline, cap hard, and optionally keep adapting it slowly from non-candidate frames (EMA with a long time constant, frozen for bands currently tracked as candidates) so a song starting after arming does not become 'feedback'; document that watch calibration is a baseline, not a noise floor.
Interaction with prominence: prominence_db over the ±neighbour_bins median is a spatial floor (rejects broadband energy at one instant); the per-band baseline is a temporal floor (rejects stationary narrowband features — rumble, HVAC/PA hum, a room mode — that ARE spatially prominent but predate arming, which is what spent the budget at M7). They are complementary and both cheap; with the temporal baseline the 40/80 Hz false notches are rejected even before the frequency window lands, and the prominence override (25 dB/6 frames) should also require level above baseline so a pre-existing hum cannot trigger it.
Config: detector.floor_margin_db (8), floor_sample_s (2.0), floor_sample_frames (40), floor_cap_db (-30), floor_percentile (0.9), min_hz/max_hz; floor_margin_db 0 disables. Tests: (a) SyntheticRta defaults (loud LF slope) + calibration + inject_ring(2400, 20, -34) -> notch still lands at GEQ 22 within 3 s of the detector going live and arm result says calibrating; (b) Room source with a -50 dB line at band 5 and -90 elsewhere -> gate for band 5 = -42, other bands stay at min_level_db, floor_db reported -50; (c) a -20 dB stationary hum inside the window present during calibration is NOT notched afterwards, a new -30 dB ring two bands away IS; (d) ring_out does not RAISE before cfs.stage ARMED/calibrated; (e) cfs_status shows floor/gate; (f) no frames -> uncalibrated flag, cfg unchanged.

## Part A — Arm-time noise-floor calibration, done right

### A.1 Decisions (binding)

| # | Decision | Rationale |
|---|---|---|
| A1 | Calibration is a **CALIBRATE phase of the detector task** (`CfsManager._consume`), on the frame timeline: discard `floor_settle_frames`, collect a sample, install per-band gates, then start judging. It never runs in `_open_session` (no frames; also holds `_lock`), never in `_arm`/`feedback_watch` (holds `_lock` and the tool call for the window, and ages every cache entry preflight primed). The arming call returns immediately. | HEAD's placement is a guaranteed no-op + 0.3 s stall; Jim's placement caused Bug 4's timing. |
| A2 | **Per-band gate vector**, not a global scalar: `gate[i] = min(cap, max(min_level_db, floor[i] + floor_margin_db))`, `cap = max(floor_cap_db, min_level_db)`. Calibration only ever raises the configured gate and never above the cap. | Room noise is coloured (M7: 48 Hz rumble 40 dB over the 8 kHz hiss). A global gate from the loudest band either deafens 2–8 kHz (SyntheticRta: 20 Hz band ≈ −9.5 dB → gate −1.5 dB → no detection at all, the lead's variant (a)) or lets rumble through. |
| A3 | **Statistic**: `floor[i]` = the `floor_percentile` (default 0.75) quantile over the sample of `min(level[i], median(neighbours ±neighbour_bins, excluding i) + prominence_db/2)`. Never max-of-frames, never max-of-bands. | p75 tolerates 25 % transient frames (a door slam is 2–6 of 20 frames) yet sits ~1.5 dB above typical for ±3 dB flutter; + 8 dB margin clears the flutter's own maximum. The neighbourhood clamp (same median the prominence test uses, detector.py:278) stops a narrow peak that is ALREADY present while measuring (an established ring, mains hum) from lifting its own gate: clamped it contributes `median+6`, so its gate is `median+14` ≈ the prominence threshold, and it stays catchable. Verified numerically: −40 dB tone over −90 dB hiss with −50 dB leak → clamp −84 → gate = `min_level_db`. |
| A4 | **Hard cap** `floor_cap_db` default −30 dBFS (RTA scale). Bands whose `floor+margin` exceeds the cap are counted (`capped_bands`) and produce a session warning ("loud room / programme during calibration; gate capped at −30 dB in N band(s), loudest F Hz"). | Anything at or above −30 dBFS on a bus RTA is loud enough to be judged on prominence/persistence/growth alone; M7's missed howl plateaued at −25. A loud room may desensitise the detector below the cap, never deafen it. Pick the final number on hardware in a loud room. |
| A5 | **No master-tracking offset in ring-out.** The gate vector measured at the operator's start level stands for the whole run. | The RTA taps the bus PRE-/POST-EQ, upstream of the bus/main fader (meters.md §5.3, `/-stat/rtasource` 48+N−1 / 146+N−1; HANDOVER §4b item 4 confirms the tap sits between the PRE and POST insert points). Raising the master does not move direct programme or mic-borne room noise at the tap; what rises with the master is only the regenerative component — exactly what must be detected. An offset dB-for-dB (write-failure worktree f9a5c56 `level_offset_db`) would push every gate to the cap over a 25 dB ring-out for no physical reason. Drop it. Hardware check to log at the M7 re-test: floor summary at start level vs after +10 dB of raise should agree within flutter. |
| A6 | **One-shot per session.** A slow tracking floor (EMA τ≈5 s over non-candidate bands, frozen within `band_tolerance+1` of any live candidate, attack-only downward… ) is explicitly deferred; document it as the follow-up for long watch sessions with drifting programme. | Minimal change; a tracker done wrong learns a slowly growing ring into the floor. |
| A7 | **Nothing is judged during CALIBRATE** (`det.feed` is not called on settle/sample frames). | Feeding under the uncalibrated gate is what notched rumble "within seconds of arming" at M7. Cost: an already-howling ring is caught `settle + sample + override_persistence` ≈ 0.25+1.0+0.3 s after frames start instead of 0.3 s; A3's clamp guarantees it IS caught then (test A.6-I3). |
| A8 | **Watch and ring-out share the code path.** Ring-out adds a CALIBRATE stage between ARM and RAISE: it awaits the floor (bounded), then LISTENS one persistence window at the untouched start level before the first raise, so a ring that exists at the start level is handled before any gain is added. | Frames start at ARM after SNAPSHOT with nobody playing: the ideal moment. |
| A9 | In **watch** the "floor" is a per-band baseline of whatever was present at arm (programme may be playing). It is documented and reported as such (`kind: "baseline"` vs `"floor"` is NOT introduced — one field `programme_suspect: bool` = `capped_bands > 0 or floor_median_db > floor_cap_db − 20`). It is not a music/feedback discriminator: content that starts after arming sails through it; the frequency window / harmonic test (BRIEF §1) remains the fix for the 40/80 Hz false positives. | Honest semantics; the cap bounds the harm of measuring over music. |
| A10 | **Prominence stays as is.** Prominence is the spatial floor (band vs neighbours, same instant: rejects broadband lifts — crowd, master, chorus); the calibrated gate is the temporal floor (band vs its own pre-arm history: rejects stationary narrow features — rumble, hum, a room mode — that ARE prominent but predate arming). Feedback is narrow AND new; requiring both does not double count. The established-feedback override (detector.py `_score`) is unchanged and still subject to the gate (a pre-existing 25 dB-prominent hum above the cap is, correctly, still emitted — it is loud enough to matter). | |

## Part B — A cut is a transaction: controller, report and desk can never disagree

### B.1 Invariant

For every session, at every await point and in every report: `NotchController.gains/notches/touched` ⊆ what the desk has acknowledged by read-back; `CfsState.notches`, `budget_left`, `cfs.notch` events, `notch_log` and report `notches` derive only from committed (= confirmed) cuts; a cut in flight when a session ends either lands (and is everywhere) or does not (and is nowhere); the report additionally carries a finish-time reconciliation against a fresh GEQ read.

### B.2 detector.py — two-phase `NotchController` (line 500+)

1. New frozen dataclass `NotchProposal(bus: int, band: int, freq_hz: float, current_db: float, new_db: float, opens_band: bool, session_id: str, ts: float)` with `depth_db` property = `new_db`; exported.
2. `propose(self, det: Detection, bus: int, session_id: str) -> NotchProposal | None`: exactly `plan`'s band choice (551-565) and `_apply`'s depth arithmetic + `self._validate(current, new)` (may raise `PolicyError`), but mutates NOTHING. `opens_band = band not in self._touched`.
3. `commit(self, p: NotchProposal) -> Notch`: refuses a stale proposal (`abs(self._gains.get(p.band, 0.0) - p.current_db) > 1e-9` → `ValueError`), then performs `_apply`'s mutations (567-585) and returns the `Notch`. `_apply` is deleted.
4. `plan()` stays as `propose()`+`commit()` for `RecordingGeqWriter` simulations and existing unit tests; docstring: "cfs never uses this: it writes between the two".
5. `resync(self, gains: Mapping[int, float]) -> None` (used by reconciliation, B.4-6): replace `_gains` with the desk's values; drop `_notches[b]` whose desk gain is ≥ −ε (keeping `_touched` — budget spent stays spent); update `depth_db` of the rest.
